# Scientific Validation & Ablation Setup

## 1. Knowledge Graph Ablation

Your implementation supports three configurations to report performance lift:

- **Base HGCDR++**: Set `enable_kg: False` in `configs/config.yaml`.
- **KG (Strict Only)**: Run `align_kg.py` without semantic matching enabled (see script comments) or use only strict `.link` edges.
- **KG (Hybrid)**: Current Default. Uses `amazon_item_to_kg.csv` generated by strict + fuzzy matching.

## 2. Oversmoothing Diagnostic

- **Metric**: `[Diagnostic] Latent Alignment CosSim`
- **Where**: Logged every 10 batches in `training.log`.
- **Interpretation**:
  - Values < 0.90: Healthy alignment.
  - Values > 0.95: Potential Oversmoothing (User Source/Target embeddings collapsing). If observed, try increasing `lambda_contrast`.

## 3. Inference Design Choice (Paper Justification)

**"Why do you use ID Embeddings for inference instead of HGT output?"**

- **Design Choice**: For real-time inference, we utilize the **Cached ID Embeddings** (`tgt_item_emb`) rather than contextual HGT embeddings.
- **Reasoning**: Evaluation requires ranking 1000+ candidates per user. Computing the full HGT graph forward pass for every user-candidate pair violates the <100ms latency budget.
- **Validity**: The ID embeddings are updated during training via backpropagation from the HGT output, so they "distill" the graph signal into atomic representations.
